# Безопасная работа с сайтом

Эти правила входят в репозиторий, чтобы сохраняться в отдельных worktree и клонах.
Перед правками прочитать `docs/repository-boundary.md`; для анимаций также
`docs/motion-system.md`. Если доступен родительский README проекта, прочитать его.

## Перед каждой задачей

1. Проверить Git-корень, текущую ветку, HEAD, staged/unstaged/untracked изменения
   и список worktree. Сохранять чужую и незавершённую работу.
2. Выполнить fetch origin, проверить расхождение с origin/main; при работе от
   опубликованной версии сверить SHA успешного Pages deploy. При недоступной сети
   явно сообщить, что актуальность не подтверждена.
3. Сообщить пользователю рабочую папку, ветку, наличие локальных изменений и
   расхождений. Не называть main опубликованной версией без проверки.
4. Параллельную независимую задачу вести в отдельной ветке и отдельном worktree
   от актуального main; сначала проверить существующие рабочие копии. Создание
   worktree для такой изоляции разрешено этим правилом. Не переключать ветку в
   папке другого чата. Каждому просмотру назначить свободный порт и назвать URL.
5. Проверить локальные scripts/hooks. При отсутствии существующих hooks включить
   `.githooks` через локальную настройку core.hooksPath; существующие hooks
   не перезаписывать. Старым веткам может требоваться перенос инфраструктурных
   изменений. GitHub-защита не устанавливает локальные hooks автоматически.

## Сохранение и выпуск

- Не применять reset/clean/stash ради упрощения работы. Не копировать старые
  файлы поверх новых целиком для разрешения конфликтов.
- Коммит и push выполнять только с явного разрешения пользователя. Push рабочей
  ветки и публикация сайта — разные действия; сообщать их статус отдельно.
- Перед объединением включить свежий main в рабочую ветку и проверить совместный
  результат. Выпускать задачи последовательно. Отсутствие конфликтов не заменяет
  проверку дизайна и поведения. Не использовать force push в main.
- Основной локальный main обновлять только чистым fast-forward. При локальных
  коммитах или грязной папке сохранять работу и остановить автоматическое обновление.
- После публикации проверить SHA удалённого main, успешного Pages deploy и
  основной локальной папки, а также живой сайт. Не удалять неперенесённую работу.
- Сборка, визуальная проверка и публикация — отдельные результаты. Для UI проверить
  EN/RU, desktop/mobile, Birdview/Snakeview, системные темы; для motion — reduced motion.
- Не обещать постоянное совпадение веток: удалённый main может обновиться при
  выключенном компьютере. Перед каждой новой задачей сверять состояние снова.
