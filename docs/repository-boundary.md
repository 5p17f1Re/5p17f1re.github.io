# Граница репозитория

Этот репозиторий содержит только публикуемый сайт-портфолио и документы, необходимые для его разработки и поддержки. Personal OS не является частью репозитория сайта.

## Отправляем в Git

- код и данные сайта: `app/`, `components/`, `data/`, `styles.css`, `mdx-components.tsx`;
- инструменты сборки и проверки: `scripts/`, `tests/`, `package.json`, `pnpm-lock.yaml`, конфигурацию TypeScript, ESLint и Next.js;
- workflow публикации: `.github/workflows/`;
- код и миграции photo publishing backend: `publisher-worker/`;
- документацию по устройству и обновлению сайта: `docs/` и `media-originals/README.md`;
- только готовые публичные изображения и видео из `public/media/`;
- готовые публичные производные фотографий из `public/photos/`;
- публичные индексы медиа `generated/media-manifest.json` и
  `generated/photo-media-manifest.json`;
- публикационные записи фотографий из `data/photos.json` и типизированный доступ
  к ним из `data/photos.ts`.

## Не отправляем в Git

- Personal OS и его материалы: вакансии, резюме, заметки, исследования, черновики, `raw/`, `wiki/`, `private/`, `work/`;
- черновики публикационных текстов: `content-drafts/`; утверждённый канон остаётся в Personal OS;
- локальные оригиналы изображений и видео из `media-originals/`;
- временные копии фотографий из Cloudflare R2: R2 остаётся внешним приватным
  staging и никогда не синхронизируется в Git;
- результаты сборки и локальное состояние медиапайплайна: `.next/`, `out/`, `generated/media-state.json`;
- локальные зависимости, настройки и диагностику: `node_modules/`, `.DS_Store`, `.idea/`, `.vscode/`, логи и отчёты покрытия;
- секреты и учётные данные: `.env*` (кроме `.env.example`), ключи и сертификаты.
- файлы `public/fonts/ABCAreal-*.woff2`: бесплатная лицензия Dinamo разрешает веб-использование, но запрещает публикацию файлов шрифта в открытом Git. Для локальной сборки скачай Areal с [официального сайта Dinamo](https://abcdinamo.com/free/areal) и скопируй `ABCAreal-Regular.woff2` и `ABCAreal-Bold.woff2` из папки `WOFF2/` в `public/fonts/`. GitHub Pages получает те же файлы из закрытых Actions secrets перед сборкой; посетители загружают их с этого сайта по `/fonts/…`.

## Перед коммитом

1. Работать и коммитить только из `site-nextjs/`.
2. Добавлять файлы точными путями; не использовать `git add .`.
3. Проверить список подготовленных файлов и убедиться, что каждый относится к сайту или его документации.
4. После изменения оригиналов выполнить `pnpm prepare-media` и добавить только
   изменившиеся публичные варианты вместе с manifest.
5. Выполнить `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build` и `git diff --check`.
6. Перед отправкой убедиться, что в подготовленных изменениях нет ключей, токенов, HTML-снимков внешних сайтов или материалов Personal OS.

## История решений

Канонический журнал принятых технических и визуальных решений находится в
[`docs/decision-log.md`](decision-log.md). Каждое принятое изменение нужно записать
туда до коммита: что решили, почему, какие границы затронуты и чем проверили результат.
Если новое решение заменяет старое поведение, запись должна явно описать причину
замены. Этот журнал является постоянной частью workflow и не заменяется одним
сообщением коммита.

## Источник публикационного контента

Personal OS хранит факты кейсов, авторство и утверждённый текст. В репозиторий сайта переносится только готовый к публикации результат, необходимый для работы публичной версии.


## Локальная синхронизация и защита публикации

- `pnpm sync:check` обновляет сведения об `origin/main` и показывает, есть ли
  локальный черновик. `pnpm dev` выполняет эту проверку перед запуском.
  Устаревший или разошедшийся `main` и недоступная сеть блокируют обычный запуск.
  Отдельная рабочая ветка явно отмечается как локальный вариант.
- `pnpm sync:main` обновляет только чистый `main` без локальных коммитов,
  исключительно fast-forward. Изменения не удаляются и не прячутся автоматически.
- Локальный hook `.githooks/pre-push` устанавливается настройкой
  `git config --local core.hooksPath .githooks` после проверки существующих hooks.
  Он запрещает отправку в `main` из другой ветки, удаление `main`, публикацию
  с незакоммиченными/новыми файлами и переписывание удалённой истории.
  Для нового клона установку нужно повторить; существующие hooks не заменять молча.
- Hook является локальной защитой и может быть обойдён; GitHub Actions и веб-интерфейс
  требуют отдельных ограничений. Фото workflow должен работать только от `main`
  и использовать обычный push: конкурентное обновление сайта останавливает отправку.
- Совпадение Git-веток не доказывает успешную публикацию. После выпуска отдельно
  сверять локальный main, удалённый main и SHA успешного Pages deploy.
  Пока компьютер выключен, удалённый контент может обновиться; перед следующей
  работой выполнять синхронизацию. Автоматически перезаписывать локальные правки нельзя.
